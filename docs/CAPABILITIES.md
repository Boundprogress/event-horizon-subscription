# EH 能力与工作方式

EH 为网页 Agent 提供页面信息、可操作目标和执行回执。模型负责理解任务、规划和选择下一步；EH 负责把当次网页状态整理出来，并执行通过检查的操作。

## 能力如何体现在任务里

| 能力 | 可以怎样使用 | 公开 demo 中的例子 |
| --- | --- | --- |
| 读取页面结构 | 按区块读取文字、字段、列表和可交互对象 | 从工作台读取统计，再打开说明弹窗 |
| 条件筛选与排序 | 输入条件、切换选项、排序后核对结果 | 商品类别/新品筛选；按价格寻找目标 |
| 多条件表单 | 同时处理日期、地点、时段、数值和勾选项 | 查询指定路线、出发时间、票价上限和余位 |
| 分页、详情与关联页 | 从列表进入详情，继续读取关联对象 | 公告翻页后，跳转关联商品核对字段 |
| 动态页面变化 | 处理弹窗和新页面，依据新状态继续决策 | 先读取营业调整公告，再整理常规营业时间 |
| 跨站串联 | 把不同网站取得的信息放进同一个约束问题 | 航班与铁路查询后核对转场、到达时间 |

这些是已有公开运行的任务类型。具体演示条件和结果在 [历史实测与核对入口](DEMO_EVIDENCE.md) 中，不构成任意站点都能完成的保证。

## 一次操作怎样形成闭环

1. 读取当前页面的结构、布局与控件状态，给 Agent 提供当次可用信息。
2. Agent 根据目标和约束选择对象与动作。
3. 执行前检查相关条件；目标失效、不可编辑或操作受阻时，返回可核对的状态。
4. 返回动作回执和后续页面信息，Agent 据此决定继续、重新感知、缩小结论或停止。

页面改版、浮层切换和滚动都可能改变可用对象。旧引用不能仅凭上一次“点过了”就继续使用。动作完成、任务结果已经交付、结果每个字段都正确，需要分别核对。

这里的页面信息主要来自浏览器结构采样，不以截图 OCR 作为主要输入。结构属性、可访问性信息和布局都可能参与建模，不能理解成“完全不受前端实现变化影响”。

## 适合的使用方式

- 多个站点或多种交互混合的查询、筛选、表单和资料整理。
- 要求来源、数量、字段或时间衔接都明确的任务。
- 需要根据实际页面变化调整路线，并在结果未确认时停止核对的流程。

对于同一站点的大批量固定结构采集，正式 API 或授权数据接口通常更直接。EH 的交互读取与模型决策都有开销；不能由少数演示推导所有任务的速度和成本。

## 需要先验证的边界

Canvas 内部内容、缺少可识别语义的图标、复杂联动、虚拟滚动，以及登录态或验证码变化，都可能中断任务。当前不把这些情况视为普遍可完成的能力。更换模型或宿主后，也应重新验证规划、停止和交付质量。

操作权限、敏感站点与私有网络限制仍然有效。公开只读任务的结果，不能直接证明购买、删除、支付、授权或提示词注入场景的完整防护效果。

当前订阅客户端不提供任务记录页，也不自动保存或回放任务正文历史。本次操作仍可由 Agent 沿原请求号核对状态；这与 demo 仓库中公开保存的实验材料是两回事。
