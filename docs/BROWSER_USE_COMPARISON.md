# 从网页操作到可核对的交付

[中文](BROWSER_USE_COMPARISON.md) | [English](BROWSER_USE_COMPARISON.en.md)

**0 条站点规则 · 真实操作 · 交付可核对**

网页自动化的价值，体现在用户能否拿到符合要求的结果：搜索到目标、填好条件、打开详情，再把所需字段和来源整理回来。

## 已有讨论提供的共同背景

Browser Use 社区过去的公开讨论已涉及操作反馈、会话延续与结果核验。这些是浏览器自动化实践中已有的问题背景。其[官方输出说明](https://docs.browser-use.com/open-source/customize/agent/output-format)也区分任务结束与 Agent 自报成功，并提示对重要外部结果进行核验。

这里沿用的基本要求是：**操作有反馈，结果有依据，未完成的部分说清楚。** 这些历史讨论不用于判断 Browser Use 当前版本的表现；实际能力应结合版本、模型、配置与任务验证。

## EH 把这些要求落实到怎样的使用体验？

EH 为已有 AI Agent 提供网页操作能力。你描述目标与条件，Agent 根据当前页面选择下一步，再将状态、页面依据和整理结果交回当前对话。

| 你的需要 | EH 提供的使用方式 |
| --- | --- |
| **换站点，减少规则维护** | 0 条预写站点规则：用户无需逐站编写选择器或固定点击脚本，同一套工具用于不同网页。 |
| **完成实际网页操作** | 搜索、点击、填写、筛选排序、翻页、详情与弹窗交互，操作后返回回执与后续页面信息。 |
| **拿到可核对的交付** | Agent 按要求整理对象、字段、数量与来源，分别核对操作进展和最终答案。 |
| **受阻时知道停在哪里** | 目标不可操作或结果未确认时，说明状态与缺项；原请求号可查回，再决定继续还是交回用户。 |
| **沿用现有工具与登录态** | 通过 MCP 接入能加载本机工具的 Agent；专属 Chrome 保留网站允许持久保存的登录态。 |

这些是 EH 的产品重点；具体任务的规划、操作选择与答案整理仍由 Agent 负责。

## 带着真实任务选择

如果你正在评估 Browser Use、Playwright MCP 或其他 browser automation 工具，可以先选一项结果要求明确的任务，例如“按日期和价格筛选条目，进入详情核对字段，并附来源”。

关注四个实际问题：

1. **能否接入**：宿主能否加载工具，浏览器是否已连接。
2. **能否操作**：目标页面能否读取，必要控件是否可用。
3. **能否交付**：结果是否满足对象、字段、数量与来源要求。
4. **是否值得持续使用**：用时、模型费用、服务用量和人工核对成本是否合适。

## 使用前了解这些边界

- **0 条站点规则是使用方式**：用户无需逐站预写规则；页面变化、复杂控件、Canvas、登录验证与访问限制仍可能影响完成情况。
- **本机浏览器，云端处理**：Chrome 在本机，页面采样需要发送到云端 EH；当前处于公开测试阶段，新账号注册成功即自动获得 1000 帧一次性免费总额度，永久有效，用完即止，不按月重置。
- **结果仍需验收**：操作回执、任务交付与每个字段的事实正确分别核对，不能互相替代。
- **记录范围要确认**：客户端不自动保存或回放任务正文历史；原请求号查回与长期历史回放是不同能力。

能力范围见 [能力与工作方式](CAPABILITIES.md)，具体使用问题见 [FAQ](FAQ.md)。[历史公开演示](DEMO_EVIDENCE.md)保留各自的版本、样本和核验条件，不作为当前任务的效果保证。
