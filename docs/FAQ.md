# EH 使用与能力 Q&A

这里选择 demo 中常见的问题，按当前订阅版重新整理。需要复核历史数字时，请看 [历史实测材料](DEMO_EVIDENCE.md)；原版 [demo Q&A](https://github.com/Boundprogress/event-horizon-demo/blob/ac0236cd19560efa5f43ba350bbc599ff4158fc4/QA.md) 中关于测试开放、安装、截图和许可的旧说明不直接适用于本版。

## 是为每个任务录好的点击脚本吗？

公开演示中，驾驶模型根据当时页面选择下一步，同一道题可以走不同路线。当前订阅版通过 MCP 向自己的 Agent 提供工具；任务目标、规划和停止决定仍由 Agent 负责。

这不意味着任意站点都无需适配。页面结构、控件语义、复杂联动和前端变化仍可能影响结果，需要验证。

## 读的是截图还是页面结构？

主要输入来自浏览器结构采样，包括可见内容、布局和控件状态等，不以截图 OCR 作为主要输入。结构属性和可访问性信息可能参与整理，不能把它理解为完全不看页面实现细节。

当前订阅服务默认运行路径关闭页面截图。demo 的历史录像、页面证据和当时的采集设置，按对应实验材料解释。

## 它更适合什么任务？

适合多步骤查询、条件筛选、列表与详情联查、表单交互、跨站信息整理等有明确目标和约束的授权任务。六题实况提供了分页、排序、弹窗与关联跳转的具体例子。

固定站点的大规模重复采集，正式 API 或授权数据接口可能更合适。每步页面读取与模型决策都有开销，不能从单次演示推导所有任务的速度或费用。

## 换一个模型或本地模型就能一样好用吗？

接入协议可以复用，但模型能力、宿主环境、提示、预算和停止策略都会影响交付。宿主需要能访问本机文件并加载 MCP 工具。小模型和不同环境的实际可用范围，应单独测试。

## “执行成功”“交付通过”“事实正确”有什么区别？

执行成功说明相应操作获得了执行回执；交付通过说明满足某套交付检查；事实正确还需要逐项对照页面、来源、数量、日期等要求。它们是不同结论，不能用结束记录或模型一句“完成了”互相代替。

结果不确定时，用原请求号核对当前状态，不换一个编号重复操作。

## 有没有不能直接承诺的场景？

Canvas 内部内容、没有可靠语义的图标、复杂动态控件、虚拟滚动及登录/验证码变化，都可能造成缺口或中断。EH 不提供绕过登录、验证码、访问限制或平台规则的能力。

只读查询的演示也不能证明所有购买、支付、删除、授权或提示词注入场景的防护完整。任务授权和当前产品限制始终有效。

## 页面数据是否一直留在本机？能查任务历史吗？

浏览器在本机，页面采样仍需要发送到云端 EH 处理。当前客户端不提供任务记录页，不自动保存或回放任务正文历史；服务端正文仅作有界短暂交付。原请求号查回与最小防重元数据仍保留。

Agent 自己的对话、用户导出和浏览器数据由用户管理。具体范围见 客户端内展示的《EH 订阅服务使用协议》。

## 私有部署或企业流程怎么沟通？

可邮件说明运行环境、模型接入、目标站点、网络与数据边界、操作授权和希望交付的范围，再确认具体方案。历史 OA 沙盒探索只说明探索过相应路线，不等于当前所有企业流程都已验证。
